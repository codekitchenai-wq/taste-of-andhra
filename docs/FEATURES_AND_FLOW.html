The Taste of Andhra — Features & Flow

Online restaurant platform: storefront, kitchen ops, delivery fulfillment, and platform Master (SaaS Phase 1).

Updated: 2026-07-28 Stack: React · Vite · Supabase · Razorpay · Maps Source: docs/FEATURES_AND_FLOW.md

1. Overview

Customers browse Andhra cuisine and place delivery orders. Admins run the menu and kitchen board. Delivery partners fulfill assigned runs. A platform Master role oversees tenancy as the product moves to multi-restaurant SaaS.

Layer Technology
Frontend React 19, TypeScript, Vite 8, Tailwind CSS 4, React Router 7
Backend / data Supabase (PostgreSQL, Auth, Storage, RLS, Edge Functions)
Payments COD · Razorpay (UPI / cards / netbanking / wallets)
Maps Google Maps JavaScript API
Deploy Vercel (static SPA)

5. Checkout (customer)

  1. Select fulfilment branch (if branches exist).
  2. Select or add delivery address (Maps pin when API key is set).
  3. Optionally apply coupon and/or loyalty points.
  4. See delivery charge (rate card or live quote).
  5. Choose COD or Pay Online (Razorpay; demo if key unset).
  6. Place order → cart cleared → success page.
Default pricing: tax 5%; delivery ₹49; free delivery above ₹399 (configurable in admin settings / constants).

6. End-to-end order flow

Browse / QR / Branch menu ↓ Add to cart ↓ Checkout → createOrder() → status: pending ↓ Payment record (COD / Razorpay) ↓ Admin: pending → confirmed → preparing → ready ↓ Assign partner → out_for_delivery ↓ Partner: GPS + navigate → Mark delivered ↓ Customer notified · loyalty · invoice

Status pipeline

Status Typically moved by Notes
pending System on place order Admin may confirm or cancel
confirmed Admin
preparing Admin Cancel rules tighten
ready Admin Eligible for dispatch
out_for_delivery Admin assign / system Partner sees assignment
delivered Delivery partner Completes the run
cancelled Customer (early) or admin Side exit from earlier states

Allowed transitions

From Allowed next
pending confirmed, cancelled
confirmed preparing, cancelled
preparing ready, cancelled
ready out_for_delivery, cancelled
out_for_delivery delivered
delivered / cancelled (terminal)

8. SaaS Phase 1 (Master)

App still defaults to a single organization id. Schema/types for orgs and entitlements exist; full org RLS and billing are planned. Branches are locations within one org, not separate tenants. See docs/SAAS_MULTI_TENANT_ARCHITECTURE.md.
